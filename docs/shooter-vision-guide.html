Robot frame and mounting

The robot code uses the standard WPILib frame. +X points to the front, where the robot drives forward and where the RSL is. +Y points left, toward the intake. +Z points up. Every camera and shooter offset in Constants.java is measured in this frame from the center of the robot, at floor level.

Front and back shots

The hood pivots over the flywheel to either side. The fuel leaves from one end of the hood and arcs over the robot toward the other end, so the exit point is the opposite of the direction the fuel travels.

FlywheelFuel leaves fromFuel flies towardRobot end facing the hubCamera that sees the hub
CCWBack-rightFrontFront (+X)Front camera
CWFront-rightBackBack (−X)Back camera

To aim, the robot turns whichever end needs less rotation toward the hub. That choice also decides the flywheel direction and which camera to trust.

Building the shot table

The shot table maps distance to hood angle and flywheel speed, one table per direction. It starts with one row per direction (the trench presets), so every distance gets the same shot until you add rows. Do the lab steps first, so the camera positions and hood range are real.

  1. Open a dashboard that can edit NetworkTables (Elastic, Shuffleboard or AdvantageScope) and show the Cal table.
  2. Press D-pad up for CALIBRATION. The hood and flywheel start at the table's value for the current distance.
  3. Place the robot at a marked distance from the hub. Check Cal/DistanceFt and Cal/DistanceSource. If vision isn't working, set Cal/UseManualDistance to true and type the tape-measured distance into Cal/ManualDistanceFt.
  4. Press A until Cal/Direction shows the direction you're tuning.
  5. Adjust with the D-pad (hood 2.5° steps) and bumpers (flywheel 2 ft/s steps), or type exact values into Cal/HoodDeg and Cal/FlywheelFps. Values are magnitudes; the direction sets the sign.
  6. Hold the right trigger. The hopper feeds once the flywheel and hood are on target.
  7. When shots score consistently, press Y. Cal/LastSaved shows the saved row, or why it wasn't saved.
  8. Repeat for each distance and both directions.
  9. Copy the saved rows into ShotConstants.kFrontShots / kBackShots in Constants.java and redeploy.

1. Hood angles

  1. Robot disabled, hopper empty. The hood motor is in coast, so the hood moves by hand.
  2. In Phoenix Tuner X, open CANcoder 18 and read Absolute Position. Hood angle (°) = Absolute Position × 360. If CANcoder 18 isn't on the hood pivot shaft, note that and stop here.
  3. Zero: center the hood over the flywheel. Record the reading; it should be near 0°. If it's more than 2° off, record it so the CANcoder offset (MagnetOffset = 0.166) can be fixed.
  4. Signs: move the hood to the front-shot position (fuel leaves the back-right end). Record whether the reading is negative or positive. Repeat for the back shot. The code expects front negative, back positive.
  5. End stops: push the hood gently to each end of travel. Record both angles. Both must be inside ±90°.
  6. Usable range: for each shot, record the smallest angle where a fuel passes through the hood by hand, and the largest before the hood rubs or stops.

2. Flywheel direction

  1. Robot on blocks, hopper empty, no fuel near the shooter.
  2. Enable. Press D-pad up for CALIBRATION mode.
  3. Hold the right trigger: the flywheel spins at the calibration speed, which starts at +50 ft/s. Press the left bumper a few times to slow it down (−2 ft/s per press).
  4. Look from the robot's right side. Record CW or CCW for this positive speed.
  5. Check Shooter/FlywheelVelocity in the logs is positive too.
  6. Expected: positive = CCW = front shot. If not, the motor inversion gets fixed once in ShooterSubSystem, not in every preset.

3. Camera names

  1. Power the robot and open the PhotonVision web page (usually http://photonvision.local:5800).
  2. Record the exact name of the front camera and the back camera, including capital letters and dashes.
  3. Confirm each camera has a calibration at the resolution its AprilTag pipeline uses.
  4. Put the names in VisionConstants.kFrontCamera / kBackCamera in Constants.java. The code uses FrontCamera and BackCamera until then; a mismatch shows as a "No result from PhotonVision camera" error 5 s after enable.

4. Camera positions

Measure from the robot center (halfway between the swerve modules) at floor level to the center of each lens. Enter the results in VisionConstants.kFrontCamera / kBackCamera; the current values are placeholders.

Pitch sign. The current offsets use +30°, which means tilted down. If the cameras tilt up toward the hub tags, record it as −30°.

5. Launch point

  1. Front shot: find where fuel leaves the hood (the back-right end). Measure X (forward, so negative here) and Y (left, so negative) from the robot center.
  2. Back shot: same for the front-right end (X positive, Y negative).
  3. Enter them as ShotConstants.kFrontLaunchPoint / kBackLaunchPoint (meters). They start at 0, which aims the robot center. The aim uses Y to correct for the shooter sitting on the right side.

6. Field type

Check whether the next event uses a welded or an AndyMark field. The tag positions differ by up to about 1.5 cm, and the code has a setting for each.
